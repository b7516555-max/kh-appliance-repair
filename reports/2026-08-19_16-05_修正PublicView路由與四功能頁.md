# 修正 Public View 路由與四功能頁整合執行報告

## 一、 Root Cause 分析

先前從 LINE Rich Menu 開啟 `view=locations`、`view=status`、`view=guide`、`view=faq` 時，最後均落回預約首頁的原因如下：

1. **`applyDisplayMode()` 覆蓋重置**：
   在 `window.onload` 與 `syncData()` 的回呼流程中，執行完初期視圖切換後，緊接著呼叫了 `renderHomeEvents()` 與 `applyDisplayMode()`。
   在 `applyDisplayMode()` 內部，其 `otherSecs` 陣列僅涵蓋既有的管理或報修相關 section，未包含新增的 4 個 public sections。因此當判斷「沒有其他管理 section 開啟」時，便自動執行 `homeSection.classList.remove('hidden')`，將公開視圖強制覆蓋回預約首頁。
2. **`nav()` 控制器未註冊 Public Sections**：
   既有 `nav(sectionId)` 內部隱藏清單缺少 `locations-public-section`、`status-public-section`、`guide-public-section`、`faq-public-section`，導致無法乾淨切換。
3. **重試按鈕中的殘留 Inline 舊程式碼**：
   部分 DOM 元素中的 inline `onclick` 事件直接呼叫 `renderHomeEvents()`，干擾了單一路由管理。

---

## 二、 修正方案與架構落實

1. **建立單一 Public View 路由管理器 (`routePublicView`)**：
   - 將所有公開視圖路由統一集中管理，依 `window.APP_VIEW` 或 URL Query Parameter 進行分流：
     - `booking` ➔ `openBookingView()` (`home-section`)
     - `locations` ➔ `openLocationsView()` (`locations-public-section`)
     - `status` ➔ `openStatusView()` (`status-public-section`)
     - `guide` ➔ `openGuideView()` (`guide-public-section`)
     - `faq` ➔ `openFaqView()` (`faq-public-section`)
2. **嚴格執行時機（GAS Bridge + syncData 完成後觸發）**：
   - 確保所有 `getInitialData()` 資料就緒後，再執行 `routePublicView()`，徹底解決初期資料未載入即被覆蓋之問題。
3. **保障 Hash Routing 最高優先權**：
   - 包含 `#walkin-EVENT_ID`（現場補位）與 `#tv-board`（電視牆看板）在進入 `routePublicView()` 時優先保留並執行對應邏輯，不破壞現場作業。
4. **擴充 `nav()` 與 `applyDisplayMode()`**：
   - 將 4 個全新 Public Sections 完整納入 `sections` 控制陣列，確保任何視圖切換時 DOM 容器互相排他、乾淨顯示。

## 三、 四大公開視圖功能與資料來源

1. **維修據點 (`view=locations`)**
   - **資料來源**：`Code.gs` / `getInitialData()` 之 `events` 資料陣列。
   - **南鳳山清潔隊**：高雄市鳳山區國泰路一段69巷1號（每月第二、四週三 14:00-17:00）。
   - **楠梓家具展示區**：高雄市楠梓區清豐三路380號（週四、五 09:00-12:00, 13:00-16:00）。
   - **巡迴與推廣場次**：動態篩選未過期之非永久場次，提供 Google Maps 導航及直接帶入活動 ID 的「我要預約」捷徑。
2. **查詢進度 (`view=status`)**
   - **資料來源**：`Code.gs` 真實「維修紀錄」資料表。
   - **安全雙重驗證**：僅依「案件單號」與「手機號碼末 4 碼」驗證，絕不要求身分證或完整電話。
   - **安全脫敏公開欄位**：僅回傳單號、物品類型、品牌/型號、地點、日期、處理進度、維修結果與更新時間；查無符合或末 4 碼不符一律回傳統一模糊提示。
3. **服務須知 (`view=guide`)**
   - **資料來源**：`Code.gs` 與 `Index.html` 現行系統規則（Source of Truth）。
   - **完整規範**：
     - 【志工可修】電風扇、檯燈、吹風機、玩具、小型家電。
     - 【不受理】冷氣、冰箱、洗衣機、電視機、高壓及高危險設備。
     - 【待現場判定】微波爐、烤箱、音響等。
     - 【流程與費用】7 大無紙化流程、零件耗材工本費由民眾自行負擔、每人年度限 5 件且每場限 1 件。
4. **常見問題 FAQ (`view=faq`)**
   - **資料來源**：系統現有規則、須知與 Email 文案整理。
   - **手機 UI**：Accordion 手風琴展開式互動卡片，清晰收納 10 大常見問題。

## 修正摘要

原畫面把「未報到預約者」當成可釋出的補位名額，因此原預約 1 件且未報到時會顯示可補位 10 件。現改為以活動開始時的線上預約數建立固定快照：總容量 10、開始時已有 1 件線上預約時，現場補位容量固定為 9 件；未報到、遲到、活動開始後取消或資格失效都不會增加。

報到及現場補位改為活動開始時間開放，活動結束前 90 分鐘截止，截止時間點即拒絕。補位須先取得後端即時可用性、由工作人員輸入確認碼，再取得綁定場次及瀏覽器工作階段、10 分鐘有效且只能使用一次的授權。最後送出仍在伺服器鎖內重驗時間、名額和授權。

## 驗證邊界

- 驗收當下首頁沒有排定中的未來場次，因此沒有在正式資料上建立假預約、假報到或假補位。工作人員確認碼、授權到期、一次性、場次綁定、名額競爭等以隔離測試驗證，未污染正式試算表。
- LINE Webhook、LINE API 的目前預設選單及各 URL 已實際檢查；仍無法把「真人從官方 LINE 客戶端點擊、傳訊並看到回覆」虛報為已驗收，這一項需真人 LINE 客戶端操作才可形成完整端對端證據。
- 專案沒有 Service Worker，因此沒有 Service Worker 快取版本可更新；PWA Web Manifest 已更新並在 GitHub Pages 讀回。
- GitHub Actions 顯示其官方 Pages actions 使用的 Node.js 20 已棄用並被平台強制改用 Node.js 24；本次部署成功，這是工作流程相依套件的後續維護提醒，不影響本次功能。
